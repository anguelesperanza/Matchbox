# Phase S: changes made to the engine

You allowed me to edit engine files for phase S, on the condition that each change is written down here so you
can review it. Edits to the engine for S go in this list, newest last. Everything under `tools/mbsc/`, `docs/`
and the shader files is new work for S and is not listed; this is only what existed before.

Nothing here is committed. `git diff -- matchbox/` shows all of it.

## S2.5: the PC engine loads the generated HLSL

| File | Change | Why |
|---|---|---|
| `matchbox/render_windows.odin`, `Frame_Constants` | added `time: f32` and `_pad: [3]f32` after `view_projection` (the struct is 80 bytes now instead of 64) | the shader language has `frame.time`, and the generated HLSL declares the frame buffer with `view_projection` and `time`. The buffer the engine binds has to be the same size and layout. `time` is not filled in yet: `set_frame_constants` still builds the struct from the matrix alone, so `time` is 0. Filling it in is part of S3 |
| `matchbox/render_windows.odin`, `create_pipeline` | `#load("shaders/mesh.hlsl")` became `#load("shaders/mesh.pc.hlsl")`, with a comment saying it is generated by mbsc | the engine now uses the shader mbsc wrote from `shaders/mesh.mbs` |
| `matchbox/render_windows.odin`, `create_pipeline` | the pixel shader's entry point changed from `"pixel_main"` to `"fragment_main"` | the language names its entry points `vertex_main` and `fragment_main`; the generated file has no `pixel_main` |
| `matchbox/render_windows.odin`, `compile_shader` | the source name given to d3dcompiler, used in error messages, is `shaders/mesh.pc.hlsl` | so compile errors name the file that is loaded |
| `matchbox/window_windows.odin`, `Matchbox_Info` | one comment: `shaders/mesh.hlsl` became `shaders/mesh.pc.hlsl (generated from shaders/mesh.mbs)` | the comment named the old file |

`matchbox/shaders/mesh.hlsl` (the hand-written shader) is **kept and not loaded**. Delete it once you have run the
demo and it looks the same. Its copy for the tests is `tools/mbsc/testdata/mesh_handwritten.hlsl`, so deleting the
original breaks nothing.

### Checked without the demo

`tools/mbsc/hlsl_pixels_windows_test.odin` draws a quad with the hand-written shader and with the generated one on
Direct3D's software device, and compares the pixels: a tinted quad, a tint that changes alpha, a `uv_rect` sprite,
linear filtering, and an alpha cut-off that drops some texels and one that drops all of them. They agree to
within 1e-6 in every scene. That does not replace looking at the demo; it is why the demo should look the same.

### To check by running the demo

Run it and confirm it looks the same as before, including a sprite that uses `uv_rect` and anything with the alpha
cut-off.

Regenerate the file after changing `mesh.mbs`:

```
mbsc matchbox/shaders/mesh.mbs -target:pc --emit-hlsl -o:matchbox/shaders/mesh.pc.hlsl
```

A test fails when the committed file is out of date.

## S3: bindings and reflection

The PC engine reads `shaders/mesh.pc.refl` (made by `mbsc --emit-reflection`, format in
`docs/shader_reflection.md`) instead of hard-coding where things are bound.

| File | Change | Why |
|---|---|---|
| `matchbox/reflection_windows.odin` (new) | parses the reflection file; checks the engine's `Frame_Constants` and `Draw_Constants` against it; maps the shader's vertex attributes to `Vertex`; writes a game value into a byte block by name (`write_shader_value`) | everything the renderer used to assume about the shader |
| `matchbox/reflection_windows_test.odin` (new) | tests for all of the above, with no window or GPU | |
| `matchbox/shaders/mesh.pc.refl` (new) | the reflection file for `mesh.mbs`, committed next to `mesh.pc.hlsl` | a test fails when it is out of date |
| `matchbox/render_windows.odin`, `create_pipeline` | loads and checks the reflection file; the input layout is built from its `attribute` lines (semantic name and format from the file, offset from `Vertex`); the frame, draw and game buffers are created only if the shader declares them, the game one as big as the file says | before: three hard-coded input elements and two buffers |
| `matchbox/render_windows.odin`, `draw_item` | each constant buffer is bound at the register from the file; the draw's texture goes to the first texture the shader declares, any other declared texture gets the white texture; the sampler goes to the file's sampler register | before: `0, 2` for the buffers and `0` for the texture and sampler |
| `matchbox/render_windows.odin`, `set_frame_constants` | fills `time` with the seconds since the window was created | `frame.time` is real now |
| `matchbox/render_windows.odin`, new `set_shader_value(name, value)` and `upload_game_constants` | a game sets a `@(uniform)` by name; the value is kept in a byte copy and sent to the GPU before the next draw | the game-owned uniforms of the language. A wrong name or type stops with a message saying what the shader has |
| `matchbox/render_windows.odin`, `destroy_pipeline` | frees the game buffer, its copy and the parsed file | |
| `matchbox/window_windows.odin`, `Timestamp` | new field `start_counter`, set where `last_time` is first set | the clock `frame.time` counts from |
| `matchbox/window_windows.odin`, `Matchbox_Info` | new fields `game_constants`, `game_shadow`, `game_dirty` and `reflection` | state for the above |

### Not done

- `set_shader_value` has no `shader` argument, because the engine has one built-in shader. It comes with custom
  shaders, together with the language's `mb.set_shader_value(shader, ...)` form.
- The mesh shader declares no game uniforms, so the game buffer is not created at runtime today. It is tested by
  writing values at the reflected offsets and reading them back in a shader on the software device
  (`tools/mbsc/reflection_gpu_windows_test.odin`) and by the engine's `game_values_land_where_the_reflection_says`.
- The texture rule is "the draw's texture is the first one the shader declares". There is no way yet to bind
  a second texture per draw.
